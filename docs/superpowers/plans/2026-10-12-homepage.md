# Casa Praiamar Homepage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Build the full Portuguese Casa Praiamar homepage with the approved photo direction and a separate inquiry section below the hero.

**Architecture:** Next.js App Router with TypeScript and CSS Modules. Official copy, contact settings, and image mapping are centralized; static sections render server-side, with small client components for navigation, inquiry, gallery, and sticky CTA.

**Tech Stack:** Next.js 16, React 19, TypeScript 5, CSS Modules, sharp, Node test runner, Playwright for browser validation.

**Spec:** `AGENTS.md`, `CONTEUDO.md`, `PROMPT-TAREFA.md`, `docs/image-map.md`, and the approved `Desktop · 1440.pdf` reference. Latest user direction places no booking bar on the hero.

## Global Constraints

- Preserve official Portuguese copy and verified facts; do not add prices, availability, room imagery, or contact details.
- Newsreader 300 only on the hero h1; Jost 300/400/500 elsewhere. Host font files locally.
- Use the supplied palettes and design tokens; verify AA color pairs.
- Original photos remain untouched; generated AVIF/WebP variants live under `public/media`.
- Inquiry validates Fortaleza dates and 1–24 guests, preserves query parameters, and offers copyable text when WhatsApp is unset.

## Review Focus

- On 320–430px screens, the hero title and navigation must remain legible without horizontal overflow.
- With WhatsApp unset, the inquiry must not imply availability or confirmation.
- Invalid dates, including check-out equal to check-in, must stop submission and focus the first invalid field.
- Without JavaScript, the official page content and FAQ answers remain visible.
- Without suite photos, no gallery item or caption may masquerade as a suite.
